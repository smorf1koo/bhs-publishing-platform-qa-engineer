# Требования к учебному стенду

Стенд — упрощённая копия платформы публикации игровых проектов: каталог, карточка проекта, загрузка демоверсии и очередь модерации. Сервера нет: данные лежат в `public/data/*.json`, действия текущей сессии (загруженные демо, решения модератора) хранятся в `sessionStorage` вкладки и сбрасываются при её закрытии.

Это описание ожидаемого поведения. Если стенд ведёт себя иначе — это баг.

## Каталог (`#/`)

1. В каталоге показываются только проекты, прошедшие модерацию (`moderation_status: "approved"`). Проекты на модерации и отклонённые не видны.
2. По умолчанию проекты отсортированы по дате публикации, сначала новые. Сортировка «По названию» — по алфавиту.
3. Поиск ищет по названию проекта, без учёта регистра, по любой части названия. Пробелы в начале и конце запроса игнорируются.
4. Фильтр «Жанр» оставляет проекты выбранного жанра; список жанров строится по данным.
5. Флажок «Только с играбельным демо» оставляет проекты, у которых демоверсия опубликована (`demo.status: "ready"`). Демо на модерации не считается играбельным.
6. Фильтры и поиск действуют одновременно.
7. Строка «Найдено: N» показывает число проектов в списке с учётом поиска и всех фильтров.
8. Если ничего не найдено, показывается сообщение «Ничего не найдено…».
9. В элементе каталога: обложка, название, жанр, автор, тизер, дата публикации и значок статуса демо («Играбельное демо» или «Демо на модерации»; если демо нет — без значка).

## Карточка проекта (`#/projects/<slug>`)

1. Карточка открывается только для проекта, прошедшего модерацию. Для остальных и для несуществующего адреса — «Проект не найден».
2. В шапке: обложка, название, автор, жанр, стадия разработки, теги, тизер. Ниже — полное описание.
3. Блок «Ниша»: название ниши, число игр, медианная цена в долларах (`$9.99`, для 0 — `Free`), медиана отзывов, доля положительных отзывов в процентах с одним знаком после запятой (`84,2 %`), метод сбора и дата данных.
4. Блок «Питч»: **публичная** версия питча (поле `pitch.public_version`) — её номер, хэш и дата, и выдержка из питча. Другие версии публично не показываются.
5. Блок «Демоверсия»: для опубликованного демо — размер, дата загрузки и кнопка «Запустить демо», которая открывает демо во встроенном изолированном окне (`iframe` с `sandbox`). Для демо на модерации — «Демоверсия проходит модерацию…», если демо нет — «Автор пока не загрузил демоверсию».
6. Блок «Материалы по запросу»: перечень закрытых материалов (GDD, бюджет) и кнопка «Запросить доступ». После нажатия кнопка блокируется и появляется «Запрос отправлен автору».
7. Все даты на стенде — в формате `ДД.ММ.ГГГГ`.

## Загрузка демоверсии (`#/upload`)

1. Можно выбрать только проект, прошедший модерацию.
2. Демоверсия — web-сборка Godot одним zip-архивом. Архив проверяется в браузере сразу после выбора файла:
   - расширение `.zip` без учёта регистра (`demo.ZIP` подходит);
   - файл не пустой;
   - размер не больше 200 МБ = 209 715 200 байт (включительно);
   - файл читается как zip-архив;
   - в корне сборки есть `index.html`, хотя бы один файл `.wasm` и хотя бы один файл `.pck` (расширения без учёта регистра).
3. **Корень сборки** — корень архива. Если все файлы архива лежат в одной папке верхнего уровня, корнем сборки считается эта папка.
4. Если проверка не пройдена, показывается список всех нарушенных правил, кнопка «Отправить на модерацию» неактивна.
5. Если проверка пройдена, показывается «Архив прошёл проверку: N файлов, M байт». Кнопка активна, когда выбран и проект, и архив.
6. После отправки показывается «Демоверсия „…“ отправлена на модерацию. Заявка m-…», форма очищается, в очереди модерации появляется новая заявка, а в каталоге и карточке у проекта появляется статус «Демо на модерации».

## Очередь модерации (`#/moderation`)

1. Счётчик «В очереди: N» равен числу заявок в списке.
2. В заявке: тип (публикация карточки, правка карточки, демоверсия), проект, автор, номер заявки, дата и краткое описание.
3. «Одобрить» убирает заявку из очереди и добавляет запись в «Решения в этой сессии».
4. «Отклонить» требует причину: пустая причина или причина только из пробелов не принимается, под заявкой показывается ошибка, заявка остаётся в очереди. Автор увидит причину в уведомлении.
5. Решения сохраняются до закрытия вкладки.
